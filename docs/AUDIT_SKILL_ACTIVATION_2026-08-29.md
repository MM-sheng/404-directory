# 404.directory 安装 Skill 与首轮任务验收

日期：2026-08-29。接续服务能力发现入口一致性修复，本轮目标是让已安装的 Agent 更容易在一个真实、差异化的任务中选择 404.directory，而不是继续扩大通用功能。

## 1. 交付结论

本地已更新 `use-404-directory` Skill：自动发现描述现在首先识别“一个精确 Polymarket 市场 + 真实观察或待执行 Yes/No 动作”，而不是首先宣传官方文档搜索、网页理解等通用能力。Skill 根目录和 Claude 分发包镜像完全同步，OpenAI/Codex Skill 界面的简述和默认提示也改为预测市场风险预检。

本轮没有新增服务工具、调用付费模型、批准客户端插件、修改用户级客户端配置、提交、推送或部署。线上 Skill、市场条目和真实 Agent 使用量不会因本地修改自动变化。

## 2. 原问题

工具服务已经把 `evaluate_prediction_market` 设为第一垂直入口，但 Skill 的 frontmatter 描述没有出现 Polymarket，反而把第三方工具、官方文档、部署验证、网页理解和工具发现全部放在自动触发入口中。

这会产生两个问题：

1. Agent 只看 Skill 名称和描述时，可能在最有差异化的预测市场任务中根本不加载 Skill；
2. 普通文档或网页问题可能误触发 404，继续与模型和大厂原生能力竞争。

## 3. 已完成事项

### 3.1 收紧自动触发范围

新的自动触发描述包含：

- 精确 Polymarket URL、市场 ID 或 slug；
- 结算规则、时间边界、流动性、滑点、地域限制或执行模式风险；
- 真实 `observe`、`buy_yes`、`buy_no`、`sell_yes`、`sell_no` 决策；
- 陌生第三方 Agent 工具安装或首次使用，作为第二入口。

明确不因以下请求单独触发：赢家预测、赔率/价格查询、一般 Polymarket 教程、宽泛市场发现、没有可解析市场引用的请求，以及普通文档问题。

Supporting workflows 仍保留在 Skill 正文中，显式使用 Skill 或已经加载后仍可调用；这里只是减少它们对自动发现的干扰。

### 3.2 固定真实参数映射和安全边界

Skill 现在要求：

- `observe` 只用于不会下单的研究，不把含糊问题擅自变成交易动作；
- `supervised` / `unattended` 按真实的人类监督方式填写；
- 只有已知订单规模才填写 `estimated_notional_usd`，禁止猜测；
- 地域资格必须来自实际执行环境的当前 geoblock 结果，未检查就使用 `unknown`；
- 动作、规模、市场状态、执行模式变化或证据过期时重新评估，但禁止循环调用只为得到 `allow`；
- `allow` 不是预测、推荐、保证或交易指令；`review` 必须暂停并暴露未知项；`block` 不得继续；
- 只有真实行为或执行结果已知后，才使用一次性令牌报告 bounded outcome，禁止伪造反馈。

这些值与实际 `EvaluatePredictionMarketRequestSchema` 的枚举和约束一致。

### 3.3 同步分发与客户端入口

- `skills/use-404-directory/SKILL.md` 与 `distribution/404-directory/skills/use-404-directory/SKILL.md` 字节一致；
- `skills/use-404-directory/agents/openai.yaml` 的简述和默认提示改为预测市场第一入口；
- Claude/Codex 插件原有的第一默认提示本来就是 Polymarket，本轮保留；
- npm stdio bridge 仍保持依赖为零，dry-run 包含 4 个预期文件。

## 5. 原生客户端事实检查

只进行了只读版本和配置检查，没有发起模型调用或自动接受条款/批准：

| 客户端                         | 当前事实                                           | 结论                                                             |
| ------------------------------ | -------------------------------------------------- | ---------------------------------------------------------------- |
| Codex CLI `0.150.0-alpha.12.2` | 旧验收条目仍固定 npm `0.9.2`                       | 不能用于当前版本验收；本轮未修改用户全局配置                     |
| Claude Code `2.1.205`          | 生产 HTTP 验收入口显示已连接；打包插件显示等待批准 | 仅证明连接健康，不证明当前工具清单、Skill 自动选择或真实有用调用 |
| Cursor                         | 当前审计终端没有可调用的 Cursor CLI                | 未验证；不能沿用历史 UI 配置宣称通过                             |

因此，本轮只证明 Skill 契约和本地调用路径已经准备好，**没有证明 Cursor、Claude 或 Codex 的模型会自然选择它，也没有产生一个合格外部 Agent。**

## 7. 技能如何影响实现

`skill-creator` 促使自动发现描述保持窄而可区分，把大量条件细节留在 Skill 正文，并保留现有隐式调用策略；`agent-tool-builder` 促使每个动作、规模、监督方式、地域来源、错误恢复和结果边界与真实 MCP schema 对齐。没有添加一个新的“预测工具”，也没有把静态文案测试当成原生模型行为证明。

## 8. 下一步

下一步不是增加功能，而是发布前完成累计差异审阅，然后在不计入增长的内部身份下依次验证：

1. Claude 插件批准后的工具清单和精确市场首轮调用；
2. Codex 专用验收配置更新到待发布版本后的同一任务；
3. Cursor 干净安装后的同一任务；
4. 三个“不该触发”的预测/价格/一般教程反例；
5. 验收通过后，才邀请第一个独立运营者进行真实任务和跨日复用。
