## 2. 已完成事项

### 2.1 使用真实 MCP 注册清单作为统一来源

新增 `src/mcp/service-manifest.ts`。服务启动时通过 MCP SDK 的内存传输读取同一注册工厂的 `tools/list`、`prompts/list` 和 instructions，取得真实名称、说明、输入/输出 schema、安全 annotations 和 prompt 参数。

- 不读取 SDK 私有字段，不再维护另一套硬编码工具名称列表或简化 schema。
- 不访问外网，不调用工具处理函数，不经过 HTTP 统计中间件。
- 只在启动时生成快照；改变工具注册或功能配置后需要重启。
- 未启用的功能不进入公开服务清单；零工具、零 prompt 配置也能启动。

### 2.2 统一发现、文档和安装后的第一步

以下入口使用同一份启用清单：

- 首页工具链接、首页首个任务入口及主要 SEO 描述；
- `/tools` 和 `/tools/:name`；
- `/health`、`/mcp-info`、`/.well-known/mcp.json`；
- `/.well-known/mcp/server-card.json` 的完整 tools 和 prompts；
- `/docs.md`、`/llms.txt`、sitemap 中的工具元数据链接；
- `/connect` 和 `/connect.md` 的启用工具列表与任务示例。

关闭网关时不再引导调用 `search_official_docs`；关闭目录时不再展示强制调用预测市场工具的请求示例。默认配置仍保留原有预测市场首轮任务、稳定随机身份和客户端来源标记。

安装说明也明确：激活需要成功的业务结果，不是任意一个非错误协议响应；空搜索和连接检查不激活身份，重复调用不增加独立 Agent 数。安装身份仍不等于经过核验的独立运营者。

### 2.3 明确 HTTP 元数据与执行路径的区别

每把服务工具元数据都有：

- `kind: 404_service_tool`；
- `input_schema` 及实际注册的 `annotations`，存在时包括 `output_schema`；
- `invocation.mcp`：`/mcp`、`tools/call` 和精确工具名；
- `invocation.rest`：已有 REST 方法、路径、参数映射；没有独立 REST 等价路径则为 `null`。

`search_official_docs`、`inspect_tool_server`、`invoke_registered_tool` 明确为 MCP-only。`GET /tools/search_official_docs` 是获取元数据，不是检索文档。

已有 REST 等价操作的 OpenAPI 说明补充对应 MCP 工具名和参数转换。例：`compare_tools` 的 MCP `ids_or_slugs` 数组需要编码成 REST 的逗号分隔 `ids`；结果回报的 `receipt_id` 放入路径，剩余参数和一次性令牌放入请求体。没有改变业务请求校验或授权策略。

### 2.4 保留两个目录的边界

| 入口 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| MCP `tools/list`、`GET /tools` | 404 自身可调用的服务函数 | 全部生态工具都能执行 |
| `search_tools`、`GET /v1/tools/search` | 已注册的目标记录，包含自身工具和第三方工具 | 404 又多了一批同名服务函数；已获执行权限 |
| `list_capabilities`、`GET /v1/capabilities` | 生态记录的能力标签 | 404 服务函数名称清单 |

执行仍受生命周期、所有权验证、运营者准入、认证与网关策略限制。安全 annotations 原样取自真实 MCP 注册，不构成新的安全认证。

## 4. 兼容性与发布注意事项

1. `/tools` 保留 `{ tools: [...] }` 外层和原有核心字段，但启用完整功能时从 2 项扩展为 16 项。消费者不应硬编码数量。
2. 原生工具详情保留原有 REST/使用场景/示例等字段；schema 改用实际 MCP JSON Schema。依赖旧 OpenAPI schema 方言的消费者应改读 `/openapi.json` 的 REST 契约。
3. 新增的目录和网关工具详情应使用 `invocation`，不要假设每项都有原生 `endpoint` 字段。
4. 未启用的工具详情不再公开为可用服务工具；生态记录查询仍走 `/v1`。
5. OpenAPI 对已有服务等价操作补充了 operationId，依赖生成式客户端的集成需要检查生成结果。
6. 发现响应现有缓存策略包含一小时共享缓存和后台更新窗口。批准发布后需要核对缓存刷新及 MCP 重新连接，不能只看到新健康检查就认为所有目录都已更新。
